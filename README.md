# QEF-HGNN Heterophilic Few-Shot Benchmark

One-click, reproducible benchmark for **few-shot node classification on heterophilic graphs**, evaluating the proposed **QEF-HGNN** (Quantum Entanglement-Fractional Hybrid Graph Neural Network) and its ablations against classical message-passing and spectral/diffusion baselines.

This script is the heterophilic companion of the homophily benchmark and keeps the same code organization, tune-once/freeze protocol, split-level reporting, and paper-report outputs.

## Overview

The benchmark trains and evaluates **8 methods** on **4 heterophilic datasets** under a strict few-shot regime (4 labelled training vertices per class, 5 validation vertices per class), reporting test accuracy, macro-F1, validation accuracy, and runtime on **10 matched evaluation splits** per dataset/method.

Pipeline in one run:

1. Load and preprocess each dataset (undirected, self-loop-free graph; row-L2-normalised features; enforced C=5 classes).
2. Compute the retained Laplacian eigenspace and label-free semantic top-k neighbours (TruncatedSVD embeddings + cosine kNN).
3. Tune every method **once** on a dedicated tuning split (seed 1000) with Optuna TPE under a shared nominal budget (B=100).
4. Freeze the selected configuration and re-evaluate from scratch on the 10 matched evaluation seeds (0–9).
5. Emit CSVs, a text summary, a complete LaTeX table, per-dataset winners, a QEF-vs-baseline comparison, and an overall ranking.

## Methods Evaluated

| Group | Methods |
|---|---|
| Classical message passing | GCN, GAT, GraphSAGE |
| Spectral / diffusion | Heat-GCN, Frac-Heat |
| Operator variants and full model | QE-HGNN (s = 1), QFK-HGNN (ε = 0), **QEF-HGNN** (proposed) |

**QEF-family affinity construction (executable form).** For each row block, QEF-HGNN combines three normalized components:

```
score = H_frac + γ · S_sem + δ · ε · C_QEF
```

where `H_frac` is the fractional heat kernel in the retained eigenspace, `S_sem` is a label-free semantic affinity, and `C_QEF = -D/Z` is the **signed** first-order Duhamel correction. The signed score is **ranked before** a monotone positive weight transform (adaptive exponential); negative perturbations are never entrywise-clipped away. Setting γ = δ = 0 exactly recovers the fractional branch with identical post-processing. QE-HGNN and QFK-HGNN retain the legacy affinity path so the ablation baselines are not silently redefined.

**Downstream learner (Algorithm 2).** All operator-family methods use the same downstream pipeline: dual ridge regression on kernel-smoothed features, weighted kernel voting, and label propagation, fused into probabilities and optionally refined by balanced, confidence-thresholded self-training. Validation nodes are always protected from pseudo-label admission, and only training-split labels are ever visible to the learner.

**PennyLane role.** PennyLane is an explicit required dependency: a small Bell-pair sanity check validates the entangling primitive underlying H_sem and keeps a device-facing quantum path in the executable code. The scalable paper evaluation itself uses the first-order Duhamel approximation (see caveats below), not a full quantum simulation.

## Datasets

| Dataset | Source | Classes (enforced) |
|---|---|---|
| Texas | PyG `WebKB` | 5 |
| Wisconsin | PyG `WebKB` | 5 |
| Cornell | PyG `WebKB` | 5 |
| Chameleon | PyG `WikipediaNetwork` (geom-gcn preprocess) | 5 |

Dataset-provided masks are **ignored**; every method receives exactly the same custom few-shot splits generated by `make_split()`. Edge homophily is printed for reporting only and never used for training.

**Rare-class fallback.** Texas contains a singleton class in the standard WebKB/Geom-GCN data. When a class is smaller than the requested train+val budget, distinct vertices are assigned to training first, then validation — never duplicated, merged, or dropped. A singleton class contributes its sole vertex to training and has no validation/test vertex.

## Evaluation Protocol

- **Splits:** 4 train / 5 validation vertices per class (class-balanced, disjoint); all remaining nodes form the test set. Evaluation seeds: 0–9. Tuning seed: 1000.
- **Tune once, then freeze:** Hyperparameters are selected only on the dedicated tuning split and frozen for all 10 evaluation seeds. No test data ever influences selection.
- **Shared budget:** Every method gets the same nominal Optuna TPE cap B = 100.
  - Neural methods: single-stage search.
  - QEF-family methods: **two-stage hierarchical search** with the same total budget — Stage 1 selects the operator using a fixed low-variance downstream learner (50 trials), Stage 2 freezes the operator and tunes the downstream learner (50 trials).
- **Matched self-training:** Neural and kernel/operator families share the same rounds/threshold/pseudo-label grids; validation nodes are excluded from pseudo-label admission everywhere.
- **Early stopping:** Validation-only, within each evaluation seed. Optuna median pruning is used only during selection; the frozen configuration is always retrained from scratch on every reported seed.
- **Metrics per split:** test accuracy, macro-F1, validation accuracy, runtime (seconds).

## Scientific Scope and Approximation Caveats

These constraints are enforced in code and recorded in cache metadata / `run_metadata.json`; results must be described accordingly:

- The exact two-register Hamiltonian for QE-HGNN/QEF-HGNN has dimension **n²**. Since a fully specified scalable matrix-free exact implementation is not yet provided by the manuscript, all **ε > 0** results use a **first-order Duhamel retained-eigenspace approximation** (O(ε²) omitted).
- Results must **not** be described as an exact full n² two-register exponential (`exact_full_n2_heat_marginal: false` is written into every result row and cache metadata file).
- The theoretical raw heat marginal is PSD; the **processed classification affinity is not claimed to preserve PSD** (top-k sparsification, symmetrization, and the rank-then-transform step break PSD by design).
- QFK-HGNN uses the ε = 0 factorized fractional-diffusion branch.
- Bold entries in the LaTeX table mark the largest sample mean per column and are **descriptive, not significance claims**; the best-accuracy report is likewise descriptive.
- `FAST_DEBUG_MODE` (budget 8) exists only for smoke tests and must never be used for reported paper results.

## Installation

```bash
pip install numpy scipy pandas scikit-learn torch torch-geometric optuna
pip install pennylane pennylane-lightning
pip install pynndescent   # optional; strongly recommended for Chameleon
```

Requirements:

- Python 3.10+ (uses `X | None` union syntax and modern dataclasses)
- PyTorch (CUDA is used automatically if available; CPU works)
- PyTorch Geometric (datasets + GCNConv/GATConv/SAGEConv layers)
- Optuna (TPE sampler, median pruner)
- PennyLane (`lightning.qubit` preferred, `default.qubit` fallback)
- pynndescent (optional): approximate cosine kNN; without it the code falls back to exact brute-force neighbours with a printed warning (slow on Chameleon).

## Usage

```bash
python qef_hgnn_heterophily_residual_hierarchical.py
```

No subcommands or CLI flags. Datasets download automatically into `./pyg_data` on first run. All outputs land in `./qef_hgnn_heterophily_output_residual/`.

Results are saved **incrementally** after each method/dataset pair, so partial results survive interruption. Affinity matrices and spectra are cached on disk and reused across runs.

## Key Configuration Options

All configuration lives at the top of the script:

| Constant | Default | Meaning |
|---|---|---|
| `SEEDS` | `0..9` | Final evaluation splits |
| `TUNING_SEEDS` | `[1000]` | Dedicated tuning split |
| `TRAIN_PER_CLASS` / `VAL_PER_CLASS` | 4 / 5 | Few-shot split budget |
| `PAPER_TUNING_BUDGET` | 100 | Nominal Optuna cap B for every method |
| `OPERATOR_TUNING_BUDGET` / `DOWNSTREAM_TUNING_BUDGET` | 50 / 50 | Hierarchical split of B for QEF-family methods |
| `FAST_DEBUG_MODE` | `False` | Smoke-test mode (budget 8); never for reported results |
| `SPECTRAL_RANK` | 128 (WebKB), 256 (Chameleon) | Retained Laplacian eigenpairs |
| `SEMANTIC_DIM` / `SEMANTIC_MAX_K` | 128 / 30 | Label-free semantic embedding dim and neighbour cap |
| `KERNEL_TOPK` | 64 | Row-wise top-k of all diffusion/operator affinities |

| `ENABLE_NEURAL_OPTUNA_PRUNING` | `True` | Median pruning during selection only |

## Reproducibility Guarantees

- Global seeding of `random`, NumPy, and PyTorch (incl. CUDA, deterministic cuDNN) per training run.
- Deterministic Optuna sampler seeds derived from dataset/method names.
- Content-hashed on-disk caches keyed by the full operator/kernel configuration; every cached affinity ships a JSON metadata file recording the exact construction, post-processing, and approximation status.
- Frozen hyperparameters, tuning seeds, and the full selection log are exported alongside results.
- Strict runtime validation throughout: affinity symmetry/finiteness/nonnegativity checks, label-leakage guards (`run_algorithm2` raises if any non-training ground-truth label is supplied), and split sanity checks.

## Runtime Notes

- GPU is used automatically when available; the WebKB datasets are small enough for CPU, while Chameleon benefits substantially from GPU and from `pynndescent`.
- The per-dataset affinity/spectrum caches make repeated or resumed runs much faster than the first run.
- Total wall-clock time is printed at the end; per-split runtimes are recorded in every result row.
